## Addendum 1 (2026-09-23, AFTER) — Temuan R-38 PENTING: "100%" bukan klaim jujur

Ditabahkan setelah pengguna mengunggah hasil nyata: frontend menampilkan
**"Estimasi Hb 7.2 g/dL (Risiko Tinggi) · Keyakinan Model 100% Tinggi"** dan
menganggapnya "jelek banget" (padahal masking sudah benar). Ini bukan soal
tampilan — ini **overclaim kepercayaan palsu** dari backend.

**Akar masalah (backend, bukan frontend):** dua jalur confidence kdua-duanya bisa
mencapai 1.0 / "100%":
- `services/nail_worker.py`: `min(NAIL_MODEL_R2(0.399) + margin_factor(≤0.60), 1.0)`
  lalu `+0.08` ketika spread kecil → == 1.0.
- `models/Deploy_AnemiaEyes/deploy/inference.py`: `0.50 + margin_factor(≤0.50) → 1.0`.

**Kenapa ini melanggar:** model kuku punya **MAE ±1.6 g/dL**, mata **±1.3**.
Model dengan rentang error segini sepenuhnya **mustahil jujur mengklaim "100%
yakin"** terhadap estimasi titik — menampilkan 100% sama dengan mengarang
(R-17/R-38 "statistik palsu/batas"). Begitu pengguna mencocokkan dengan lab
sungguhan, kepercayaan langsung runtuh.

**Perbaikan yang diterapkan:**
- `nail_worker.py`: confidence = `min(R2 + margin_factor, 0.85)`, bonus
  "spread stabil → +0.08" **dihapus** (spread = proxy stabilitas, bukan
  bukti; menaikkan confidence darinya = overclaim).
- `models/Deploy_AnemiaEyes/deploy/inference.py`: confidence =
  `min(0.50 + margin_factor(≤0.35), 0.85)`.
- Kedua jalur kini **tidak pernah bisa kirim 1.0**; cap 0.85 jujur untuk band
  MAE ±1.6, cukup untuk label "Tinggi" (≥0.8) tanpa berbohong.
- Masking (kotak seg26 / heatmap mata) **tidak disentuh** — memang sudah bagus.

**Status:** DIPERBAIKI. Build/API kini tidak akan pernah menampilkan Keyakinan
100% lagi untuk kedua modalitas.
